## 0. 一句话定位

Tushare Pro 是一个**按积分收费的 A 股结构化数据 API**，
覆盖 A 股 / 港股 / 美股 / 基金 / 期货 / 期权 / 债券 / 外汇 / 宏观 全部品类，
用统一的 `pro.xxx()` 调用返回 pandas DataFrame。
**核心卖点是「字段标准化 + 复权因子 + 财务三表 + 板块分类」的组合**，
而不是行情速度。

---

## 1. 这是什么

- 运营方：waditu（Tushare 社区自己生产、开发和维护数据，**不是数据交易所转发**）
- 计价单位：**积分**（年费形式），部分接口**独立开权限、与积分无关**
- 调用形态：`import tushare as ts` → `ts.set_token(...)` → `pro = ts.pro_api()` → `pro.daily(...)`
- 官方定位原话：「由于 Pro 版是 Tushare 社区自己生产、开发和维护数据，
  围绕 Tushare 社区数据的服务器体系庞大，每年交给云服务厂商的服务器和带宽
  成本非常高，因此我们设置了积分门槛。」

### 2.1 `daily` 接口字段原文（`doc_id=27`，2026-10-09 抓取）

> 文档地址：https://tushare.pro/document/2?doc_id=27

**接口说明原文**：

> 接口：daily，可以通过数据工具调试和查看数据
> 数据说明：交易日每天15点～16点之间入库。本接口是未复权行情，停牌期间不提供数据
> 调取说明：基础积分每分钟内可调取500次，每次6000条数据，一次请求相当于提取一个股票23年历史
> 描述：获取股票行情数据，或通过**通用行情接口**获取数据，包含了前后复权数据

**输出参数原文（13 个字段）**：

| 名称 | 类型 | 默认显示 | 描述 |
|---|---|---|---|
| ts_code | str | Y | 股票代码 |
| trade_date | str | Y | 交易日期 |
| open | float | Y | 开盘价 |
| high | float | Y | 最高价 |
| low | float | Y | 最低价 |
| close | float | Y | 收盘价 |
| pre_close | float | Y | 昨收价【**除权价**】 |
| change | float | Y | 涨跌额 |
| pct_chg | float | Y | 涨跌幅（%） 【**基于除权后的昨收**计算的涨跌幅：（今收-除权昨收）/除权昨收 】 |
| vol | float | Y | 成交量 （**手**） |
| amount | float | Y | 成交额 （**千元**） |
| ah_vol | float | **N** | 盘后成交量 （手） |
| ah_amount | float | **N** | 盘后成交额 （千元） |

**输入参数**：`ts_code`（支持逗号分隔多只）/ `trade_date` / `start_date` / `end_date`，日期一律 `YYYYMMDD`。官方注：「建议提供循环日期来提取全市场数据，**不要通过循环 ts_code 来拉取历史**」。

**数据样例原文**：

| ts_code | trade_date | open | high | low | close | pre_close | change | pct_chg | vol | amount |
|---|---|---|---|---|---|---|---|---|---|---|
| 000001.SZ | 20180718 | 8.75 | 8.85 | 8.69 | 8.70 | 8.72 | -0.02 | -0.23 | 525152.77 | 460697.377 |
| 000001.SZ | 20180717 | 8.74 | 8.75 | 8.66 | 8.72 | 8.73 | -0.01 | -0.11 | 375356.33 | 326396.994 |
| 000001.SZ | 20180716 | 8.85 | 8.90 | 8.69 | 8.73 | 8.88 | -0.15 | -1.69 | 689845.58 | 603427.713 |

**三条容易看漏的事实**：

1. **`pre_close` 的官方描述直接就是「昨收价【除权价】」** —— 括号里已点明它不是原始昨收。
   由此可推出复权因子比 `= pre_close ÷ 前一根 close`。
   详见 [adjustment-principle.md](adjustment-principle.md)。

2. **`pct_chg` 官方强调「基于除权后的昨收」，但 `daily` 并不返回复权后的价格** ——
   两个口径不在同一个接口里，要拿到自洽的涨跌幅得自己合成。

3. **`ah_vol` / `ah_amount` 是盘后固定交易量额**，默认**不显示**，需在 `fields` 里显式指定：

   ```python
   # 指定提取"盘后固定成交量"和"盘后固定成交金额"数据（2026-07-06 开始有数据）
   df = pro.daily(trade_date='20260707', fields='ts_code,open,close,ah_vol,ah_amount')
   ```

**⚠️ 限流口径冲突**：`doc_id=27` 写的是「**基础积分**每分钟 500 次、每次 6000 条」，
而 §4.1 的 170 积分实测是 **50 次/分钟、8000 次/天**（§4.6 定价表对应 120 积分档）。
两者不矛盾但档位不同 —— **按实测值设计批量任务，不要照搬官网的 500 次/分钟**。

**另注**：官网 `daily` 页没有列 `pro_bar`。它的「描述」里提到的**通用行情接口**是
[`doc_id=109`](https://tushare.pro/document/2?doc_id=109)，复权行情则是
[`doc_id=146`](https://tushare.pro/document/2?doc_id=146)「复权行情」——
与 §4.1.1 的实测清单是两个东西，`pro_bar` 究竟落在哪一档限流**尚未实测**。

## 3. 优点

### 3.1 字段标准化程度高

财务三表 / 每日指标 / 复权因子都是**规范化后的结构化字段**，
拿到之后清洗工作量小。社区公认「A 股基本面数据的事实标准」。

### 3.2 复权因子 + 分红送股是两个独立的公开接口

`复权因子`（doc_id=28）和 `分红送股数据`（doc_id=103）是**分开的**，
不是只给一个拼好的复权价。这意味着：
- 想要券商口径的前复权价 → 自己拿 factor 合成
- 想要原始不复权价 + factor → 两边都有

这是很多免费源给不了的（免费源通常只给拼好的复权价，不给 factor）。

### 3.3 板块分类有三套口径（THS / DC / TDX）

同一个板块概念，Tushare 分别提供 **同花顺口径、东方财富口径、通达信口径**
三套独立的分类/成分/行情接口（`doc_id=259-261` / `362-363,382` / `376-378`）。

对多源交叉校验来说，这是**现成的口径对照组**。

### 3.4 覆盖品类远超 A 股

港股 / 美股 / 期货 / 期权 / 债券 / 外汇 / 宏观 / ETF / 公开基金 全都有，
且港美股**自带复权行情和复权因子**（`doc_id=401` 港股复权因子、`doc_id=402` 美股复权因子）。

### 3.5 特色数据是别家没有的

筹码分布 / 筹码胜率 / 券商盈利预测 / AH股比价 / 神奇九转 / 机构调研 /
开盘收盘集合竞价 / 市场游资名录 —— 这些是自建数据源几乎不可能拿到的。

### 3.6 大模型语料类接口（2026 新增）

国家政策库 / 券商研报 / 新闻联播文字稿 / 上市公司公告（10 年以上，含 PDF 下载链接）/
上证 e 互动 + 深证互动易董秘问答 —— 对做 RAG 或事件驱动的人价值很高。

### 3.7 有量化因子库

`doc_id=486 因子列表` + `doc_id=490 因子数据`，省掉自己算一遍。

### 3.8 价格极低（个人档）

A 股日频以上全品类，**200 元/年**。

## 4. 缺点 / 已知局限

### 4.1 免费额度几乎等于没有

官方表一第一行原文：

> 120 积分 · 50 次/分钟 · 8000 次/天上限 · **非复权日线数据，其他接口无法调取** · **0 元**

即：**免费只能拿不复权日线**。复权、财务、每日指标全部要钱。

### 4.2 积分与「独立权限」是两套体系，最容易踩坑

官方红字原文：

> **分钟和港美股数据权限不在积分范畴内，各类分钟单独分别开权限，且不加积分**

所以「我买了 5000 积分」**不等于**「我能拿分钟线」。分钟线要**另外** 2000 元/年。
这是整个定价体系里最容易被误解的一点。

### 4.3 分钟线是最贵的一项

| 类型 | 价格 |
|---|---|
| 历史分钟（1/5/15/30/60，2009 年起） | **2000 元/年** |
| 申万分钟（2015 年起） | 2000 元/年 |
| 期货历史分钟（2010 年起） | 2000 元/年 |
| 期权历史分钟（2010 年起） | 2000 元/年 |
| 港股分钟 | 2000 元/年 |
| 实时分钟 | **1000 元/月** |

对比：**2000 元积分能拿到全 A 股全历史日线，但一分钟线要再加 2000 元。**

### 4.4 机构价是个人价的 10 倍

官方红字：

> 以上是针对个人的价格清单，如果是公司机构，费用为个人的 10 倍。

### 4.5 不支持退款

官方红字：

> 购买后费用转入阿里云充值，因此不支持退款。

### 4.5.1 ⚠️ 170 积分实测：几乎只有 `daily` 能用

> 2026-10-07 用真实账号（170 积分）逐接口探测，**实测频次限制**：

| 接口 | 实测频次限制 |
|---|---|
| `daily` | **50 次/分钟**，8000 次/天 |
| `dividend` | 1 次/分钟 |
| `weekly` | **1 次/小时** |
| `monthly` | **1 次/小时** |
| `daily_basic` | 1 次/小时 |
| `stock_basic` | 1 次/小时 |
| `adj_factor` | 1 次/小时 |
| `trade_cal` | 1 次/小时 |
| `namechange` | 1 次/小时 |
| `stock_company` | 1 次/小时 |
| `stk_mins` | 1 次/小时 |

**这个档位的结构性后果**：

- 只有 `daily` 能全市场批量同步（实测单次可拉 8000 根，全历史到 2003-12-16）
- `stock_basic` 1次/小时 → **不能分批补全市场元信息**；
  但「一次调用拉全市场」（`exchange=''`）只需 1 次配额，5572 行可一次拿全
- `adj_factor` 1次/小时 → **全市场复权因子实际不可得**（5000 只 ≈ 208 天）
  替代路径：用 `daily.pre_close` + `dividend` 自算 factor
- `weekly` / `monthly` 1次/小时 → 派生周期应**由日线物化**，
  不要调用这两个接口（物化还避免了口径不一致风险）
- `daily_basic`（PE/PB/换手/市值）1次/小时 → 全市场估值因子需升档或另找源

**踩坑提醒**：探测这类限制时，每调一个接口就消耗掉它 1次/小时 的配额。
连续探测 10 个接口后，它们会**同时**被拒 1 小时。
错误文案形如「抱歉，您访问接口(weekly)频率超限(1次/小时)，具体频次详情：…」——
注意「每小时」与「每分钟」只差一个字，退避策略完全不同。

### 4.6 频次限制是硬约束，批量拉取容易撞墙

| 积分 | 每分钟频次 | 每天总量上限 |
|---|---|---|
| 120 | 50 | 8000 次 |
| 2000 | 200 | 100000 次/个 API |
| 5000+ | 500 | 常规数据无上限 |
| 10000+ | 500 | 常规无上限，特色数据 300 次/分 |

注意 **2000 积分档是「100000 次/天 / 每个 API」**，是 per-API 而非全局。
社区反馈的典型问题：

- 「调用频率过高被限流。基础用户的频率限制通常比较严格，比如每分钟调用多少次。
  如果你用循环批量拉取几百只股票的数据，很容易触及」
- 「财务数据的更新频率远低于行情数据，不能天天重新拉取，否则容易撞上 Tushare 的积分频率限制」

即**财务数据即使没更新，也建议按低频拉**，否则白烧配额。

### 4.7 Token 与积分绑定，泄露即等于送配额

社区实践要点：

- `ts.set_token()` 会把 token 存到本地配置文件，换机器/换用户要重新 set，否则报权限错误
- 「不要把自己的 token 随便扔到公开的代码仓库里，它和你的账号积分、调用权限是绑定的」

### 4.8 部分接口已停用或标注停止

文档树里明确标注的：

- `doc_id=164` 股票开户数据（**停**）
- `doc_id=165` 股票开户数据（旧）
- `doc_id=332` 转融券交易汇总（**停**）
- `doc_id=334` 做市借券交易汇总（**停**）

接口树里存在但可能随时变的，依赖它需要自己兜底。

### 4.9 没有本地缓存 / 没有落库

Tushare 是**纯 API**，每次调用都重新请求。
增量、落库、去重、`update_log` 这些全部要自己做。社区方案里明确提到：

> 增量更新这块是最容易被后端工程师诟病的地方。最稳妥的做法是记录一个 update_log 表，
> 每次拉数据前先查一下这个表，看股票代码加日期是否已经存在，存在就跳过。

也就是说它**只解决「取数」，不解决「存储」**。

### 4.10 没有 Level-2 / 逐笔 / 盘口

有「实时日线」「实时分钟」独立权限（200 元/月），
但**没有十档、逐笔成交、委托队列**。这些只有券商 L2 通道有。

### 4.11 实时数据按月计费且很贵

| 实时项 | 价格 |
|---|---|
| 实时日线 | 200 元/月 |
| 指数实时日线 | 200 元/月 |
| 申万指数实时行情 | 200 元/月 |
| ETF 实时日线 | 200 元/月 |
| ETF 实时参考（IOPV/申赎） | 300 元/月 |
| 实时分钟 | 1000 元/月 |

**实时是月付不是年付**，做日频研究完全用不上。

### 4.12 接口极多，查找成本高

侧边栏 20 大类、200+ 接口。想知道「哪个接口给 X」需要翻文档树，
文档树本身还分「积分接口」和「独立权限接口」两套逻辑。
官方另有[积分明细表](https://docs.qq.com/sheet/DT0FIYUxYakJ5c1FF)（腾讯文档在线表格）。

### 4.13 不覆盖 ETF 历史分钟的部分场景 / 覆盖有边界

虽然 ETF 专题列了 16 个接口，但**ETF 复权因子**（`doc_id=199`）与
**ETF 历史分钟**（`doc_id=387`）归在独立权限里，ETF 实时更是单独 200-300 元/月。

## 7. 一句话复盘

Tushare 的核心价值是**「把 A 股基本面相关的结构化字段做规整了」**——
复权因子、分红送股、财务三表、每日指标、板块三套口径，
这些是免费源和协议源都系统性缺失的部分，而价格只有 200 元/年。

它的结构性代价是：**积分与独立权限是两套体系**（买积分买不到分钟线）、
**实时按月计费**、**机构价 10 倍**、**不支持退款**，
以及**只解决取数不解决存储**（增量/落库/去重全要自建）。

**170 积分档的实测结论**：能规模化用的只有 `daily`（50次/分钟），
其余接口几乎全是 1 次/小时，财务三表与全部板块接口权限不足。
日线质量实测优秀——与 tdx2db 交叉核对 666 根 OHLC **零差异**，
volume 单位换算后相对误差 8.5e-08，amount 精度还高于 tdx2db（到元 vs 到千元）。

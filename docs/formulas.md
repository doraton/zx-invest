## 1. 涨跌额

```
涨跌额 = 收盘价 − 昨收
```

```
chg_amt = close - pre_close
```

**「昨收」有两个来源，是本项目最大的口径分歧**（涨跌额与涨跌幅共用）：

| 来源 | 含义 | 状态 |
|---|---|---|
| `pre_close` | **除权**昨收（官方口径） | 库里已存且全量非空，复权因子由它现算 |
| 前一根收盘 | 前一根 K 线的收盘价 | 前后端全部在用 |

两者只在除权除息日不等。恒生电子 2021-07-16：前一根收盘 86.50，除权参考价 61.72，当日实际收盘 **63.08**。

⚠️ `61.72` 是 `pre_close`（除权参考价 / 涨跌幅基准），**既不是当日收盘、也不是当日开盘**——
当天实际开盘 63.50、收盘 63.08。

```
用前一根收盘： 63.08 − 86.50 = −23.42   ← 假的暴跌
官方口径：     63.08 − 61.72 =  +1.36   ← 正确（与库里 chg_amt 一致）
```

**实现状态**：后端 `/api/index/quote`（`market.py` 的 `query_quote`）与十字线浮窗
（`CrosshairTooltip.tsx`）两处**已直取库里的 `chg_amt` / `chg_pct`**；
仅**图表头部**还在用「前一根收盘」（`MarketChart.tsx` 的 `prevClose`），
除权日仍会显示不存在的暴跌。

## 2. 涨跌幅

```
涨跌幅 = （收盘价 − 昨收）÷ 昨收 × 100
```

```
chg_pct = (close - pre_close) / pre_close * 100
```

昨收口径同上一节，除权日同样会算出假暴跌 —— 恒生电子 2021-07-16 按前一根收盘算是 **−27.08%**，
而库里 `chg_pct` 是 **+2.20%**（见图上 +259.87% 那个例子，§6）。

**实现状态**：与涨跌额同源，后端与浮窗均已直取库里的值。

> ⚠️ 库里 `chg_pct` 是 Tushare 的 `pct_chg`，由**未舍入的原始价**算出，落库才被
> `DECIMAL(10,2)` 截断。口径与上式一致，但**不能逐位复现**：5435 根日线里
> 有 **22 根（0.4%）**与按落库 `close` / `pre_close` 现算的结果差 `0.01`
> （如 `2005-10-26` close=5.35 / pre_close=5.53，库记 -3.26，按公式得 -3.25）。
> `chg_amt` 则 5435 根**全部吻合**。

## 3. 振幅

```
振幅 = （最高价 − 最低价）÷ 昨收 × 100
```

```
amplitude = (high - low) / pre_close * 100
```

**状态：前端完全没有这个指标**，浮窗里连这一行都没渲染。

分子分母都已在库里，是唯一「补一行就能白拿」的指标。
分母同样必须用 `pre_close` —— 用前一根收盘会在除权日算出 130% 这种荒谬值。

## 4. 换手率

```
换手率 = 成交量 ÷ 流通股本 × 100%
```

```
turnover_rate = volume / float_share * 100
```

**状态：`server/tools/calc_chips.py`（离线核算工具）里在算，前端浮窗是空占位。**

卡点全在分母 —— `float_share`（流通股本）**当前全是空值**，没有数据源接上。
数据源是本地通达信的流通股本字段。

> ⚠️ `volume` 的量纲是**手**、`float_share` 是**股**，上面这条公式要接进前端时必须先换算
> （`volume × 100` 才是股）。筹码分布内部算的时候已经处理了。

## 5. 筹码分布

> ⚠️ 下表描述的是 **`server/tools/calc_chips.py`**（离线核算工具，尚未接进页面）。
> 页面上真正跑的是 `web/src/components/ChipDistribution.tsx`，那是**简化版**：
> 把每根 K 线的 `volume` 在 `[low, high]` 上**均匀**摊到 80 个等宽价档
> （`each = k.volume / slice`），**不做换手率衰减、不读流通股本、也不是三角形分布**。
> 下表的衰减/新增/集中度只在线下工具里成立。

| 步骤 | 中文 | 英文 |
|---|---|---|
| 换手率衰减 | 筹码量 ×= （1 − 换手率），换手率 = 成交量 ÷ 流通股本，裁剪到 [0, 1] | `chips *= (1 - turn)`，`turn = volume / float_share` |
| 新增筹码 | 新增量 = 换手率 × 流通股本 | `add = turn * float_share` |
| 单日成本分布 | **三角形分布**：以 `low`~`high` 的**区间中点**为峰、两端为底，离散到价档 | 峰取 `(low + high) / 2`，底取 `low` ~ `high` |
| 获利比例 | 获利比例 = 获利区筹码量 ÷ 总筹码量 | `ratio = 获利区筹码量 / 总筹码量` |
| 集中度 | （95 分位价 − 5 分位价）÷ 均价 | `(p95 - p5) / avg` |

**守恒性**：现有断言只校验「筹码总量 == 流通股本」。
这条能抓住三角形离散化时漏乘/多乘价格步长的错误，**却抓不住量纲错误** ——
换手率算错 100 倍时它照样通过，因为新增筹码用的是同一个错的 `turn` 乘的。

## 6. 复权

> 原理详见 [adjustment-principle.md](adjustment-principle.md)。2026-10-12 已落地并全量对账通过。

| 名称 | 中文 | 英文 |
|---|---|---|
| 因子比 | 当日复权因子 = 前一根收盘价 ÷ 当日昨收（**递增方向**，见下方注） | `fac[t] = close[t-1] / pre_close[t]` |
| 累计因子 | 从上市首日 1.0 起，每遇除权日乘一次 | `cum_factor = Π fac` |
| 后复权 hfq | 价格 × 累计因子 | `price_hfq = price * cum_factor` |
| 前复权 qfq | 价格 × 累计因子 ÷ 全库最大累计因子 | `price_qfq = price * cum_factor / cum_factor_max` |
| 成交量复权 | 成交量 × （基准因子 ÷ 当日因子），**与价格反向** | `volume_adj = volume * (fac_base / fac_today)` |
| 成交额 | **不复权** | `amount` 原样 |
| 涨跌额 | 随价格一起缩放 | `chg_amt` 同比例缩放 |
| 涨跌幅 | **原样保留**（基准是已除权 `pre_close`，三种模式都成立） | `chg_pct` 不动 |

`cum_factor_max` 取**全库最后一个交易日**的因子。

> ⚠️ 因子比取 `close[t-1] ÷ pre_close[t]`（递增）。反过来取会让后复权在除权日
> **向下断**，与 adjustment-principle.md §1 的局部 ratio 定义正好相反。

**周期线（周/月/季/年）**：`kline_period` 存的是不复权聚合值，复权时**必须从日线把因子
逐根作用上去再分桶**，不能先读物化表再整体乘因子 —— 只有桶内无除权日时两者才等价。
详见 adjustment-principle.md「周期线」小节。

### 周期涨跌三列

2026-10-13 启用（见 `kline_period` §2.3）。中文：

```
上一根周期的收盘价 = 上一根 K 线的收盘价
涨跌额 = 本期收盘价 − 上一根周期的收盘价
涨跌幅 = （本期收盘价 ÷ 上一根周期的收盘价 − 1）× 100
```

对应的库列（英文写法）：

```
pre_close[周期t] = close[t-1]
chg_amt          = close - pre_close
chg_pct          = (close / pre_close - 1) * 100
```

| 点 | 说明 |
|---|---|
| 与本表 OHLC 同源 | 图上画的是原始价，数字就必须是原始口径，两者必须对得上 |
| 跨除权**显示原始跳空** | 恒生电子 2007 年线 `9.32 → 33.54` = +259.87%，库里 `chg_pct` 也是 +259.87% |
| 第一个周期为 NULL | `LAG` 天然给 NULL，不需要额外判据 |
| 复权档走别的路 | qfq/hfq 由 `market._ADJ_AGGREGATE_BARS` **现算**调整口径，不读这张表 |

> ⚠️ 这里曾经存过**除权调整口径**（`close[上桶末] × f[上桶末] ÷ f[本桶末]`）。
> 那个公式本身是对的（2021-07 真实涨幅 -16.29 就算对了），**但不该落库**：
> 调整口径和表里的原始 OHLC 不是一份东西，而 `adj=none` 时接口原样下发，
> 同一根 K 线会「图 +259.87%、数字 +369.75%」，年线上差 110 个百分点。

### 日线与周期线口径不同

别当成同一个东西：

| 表 | 涨跌基准 | 来源 |
|---|---|---|
| `kline_day` | **已除权**昨收 | 列 `pre_close`（Tushare 官方 `pct_chg`） |
| `kline_period` | **原始**上一周期收盘 | 列 `pre_close`，由 `LAG(close)` 写 |

后果：`adj=none` 下**日线仍有同样的图文不一致**，23 个除权日全部命中
（2021-07-16 图上 -27.08%、库里 +2.20%）。日线那个值是 Tushare 官方口径，
**要不要在读路径按 `adj` 换算成原始口径，待定**。

## 7. 技术指标

图形库内置实现，参数为该版本（10.0.3）源码中的实际默认值。

> ⚠️ 这一节的缩写分两类：
> `EMA` `MA` `RSV` `DIF` `DEA` **是图形库源码里的标识符**；
> `C` `O` `H` `L` `V` `LLV` `HHV` 是**常见行情软件的记法**——klinecharts v10 源码里
> **并没有 `LLV` / `HHV` 这两个标识符**（全文检索 0 次），指标 calc 实际读的是
> `kLineData.close` / `.high` / `.low` / `.volume`，`LLV` / `HHV` 是
> `getMaxMin(..., 'low', ..., 'high', ...)` 的简写记法。
> 两类都**不在数据库里**，也跟 `kline_day` 的列名对不上。
> 对照库列时：`C`→`close`、`H`→`high`、`L`→`low`、`V`→`volume`。

| 指标 | 参数 | 中文 | 英文 |
|---|---|---|---|
| MA | 20 | 最近 20 根收盘价的算术平均 | `MA = mean(close, 20)` |
| VOL | — | 成交量柱状图 | 直接取 `volume` |
| MACD | 12, 26, 9 | DIF = 12 日指数均线 − 26 日指数均线；DEA = DIF 的 9 日指数均线；柱 = 2 × （DIF − DEA） | `DIF = EMA(C,12) - EMA(C,26)`；`DEA = EMA(DIF,9)`；`MACD = 2*(DIF-DEA)` |
| KDJ | 9, 3, 3 | RSV = （收盘价 − 最近 9 根最低价）÷（最近 9 根最高价 − 最近 9 根最低价）× 100；K = （2×前一根K + RSV）÷ 3；D = （2×前一根D + K）÷ 3；J = 3K − 2D | `RSV = (C - LLV(L,9)) / (HHV(H,9) - LLV(L,9)) * 100`；`K = (2*K_prev + RSV)/3`；`D = (2*D_prev + K)/3`；`J = 3K - 2D` |
| BOLL | 20, 2 | 中轨 = 20 日均价；上轨 = 中轨 + 2 倍标准差；下轨 = 中轨 − 2 倍标准差 | `MID = MA(C,20)`；`UP = MID + 2*σ`；`DN = MID - 2*σ` |

**两处与常见券商软件不同，已核实源码：**

- **BOLL 的 σ 是总体标准差**（`√(Σ(x−μ)² ÷ n)`），不是样本标准差（÷`n−1`）。
- **KDJ 的 K、D 初值取 50**，且最近 9 根最高价 == 最低价时分母取 1 防除零。

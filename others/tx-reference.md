## 0. 一句话定位

腾讯系公开 HTTP 接口，是 A 股日/周/月 K 线数据的**第二条纯网络路径**，
原生支持复权（qfq / hfq），无需安装任何客户端。

---

## 1. 这是什么

数据来源是腾讯自选股/腾讯证券对外公开的两组 HTTP 接口：

| 接口 | 用途 | 编码 |
|------|------|------|
| `https://qt.gtimg.cn/q=<code>` | 实时快照 + 证券简称 | GBK |
| `https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=<code>,<period>,<start>,<end>,<count>,<fq>` | 日/周/月 K 线 + 复权 | UTF-8 JSON |

`param` 字段依次为：**代码, 周期, 起始日, 结束日, 数量, 复权**。
`复权` 留空 = 不复权，取值 `qfq` (前复权) / `hfq` (后复权)。

---

## 2. 优点

### 2.1 不需要装客户端

纯 HTTP，服务器端、容器、无头环境都能直接跑。
本项目已有 `external/tx_kline.py` 作为数据源模块，
4000 根日线约 **2.6 秒**拉完（翻 7 页 640 根/页）。

### 2.2 原生支持复权 —— 这是它最硬的一个长板

`param=...,qfq` 与 `param=...,hfq` 直接拿到前/后复权价。
pytdx **完全无复权接口**，tushare/akshare 等需要 token 和申请，
而腾讯 HTTP 完全免认证。

恒生电子 2026-09-30 实测：
- 不复权 close = 19.40
- 后复权 close = 824.593（累计复权因子约 42.5×）

### 2.3 实时快照带真实证券简称

`qt.gtimg.cn` 返回的字段串第 2 段就是简称：
`v_sh600570="1~恒生电子~600570~19.40~19.32~..."`

而 pytdx 完全没有名称来源（`get_security_list` 8/8 返回 None），
腾讯是少数能直接吐出中文简称的网络源。

### 2.4 行结构是 JSON

不像 pytdx 那样的私有二进制报文，腾讯是 UTF-8 JSON，
**调试肉眼可读**、翻包/抓报文/换解析器的成本极低。

### 2.5 经过三方互校

与本地 `.day` 的近 40 根 OHLC 对照：**40/40 根完全一致**，
也就是说腾讯作为**完全独立的厂商链路**，在正常区间内能
零误差地复现通达信/本地数据。

## 3. 缺点 / 已知局限

### 3.1 K 线没有成交额字段

`fqkline/get` 的每一行只有 **6 个字段**：

```
['2026-09-30', '19.380', '19.400', '19.440', '19.240', '99857.000']
   日期         开盘     收盘     最高     最低     成交量
```

**没有 `amount`，没有 `turnover`**。pytdx 协议给得到真实成交额，
腾讯这边就只能给 0 — 这是能力差距，且无法用 OHLC×volume 反推
（那不是取数据，是编数据）。

### 3.2 成交量单位是「手」，需 ×100

恒生电子 2026-09-30：腾讯返回 `99857`、本地 `.day` 是 `9985677` 股。
比例 **精确 0.0100**，即腾讯按整手存储。

后果：单根最大固有误差 99 股。聚合到周/月/季/年会被放大，
**直接和 pytdx 库对比时一定要先 ×100**。

### 3.3 字段顺序是 O, C, H, L —— 不是直觉的 O, H, L, C

```
['19.380', '19.400', '19.440', '19.240']
   O        C        H        L
```

按直觉写成 O/H/L/C 会把 C 当成 H、H 当成 L，
因为「收盘 ≈ 最高」看起来还挺像，能骗过肉眼下半年的对账。

这是腾讯最大的**入口陷阱**。`tx_kline.py` 的注释里专门标了这一条。

### 3.4 数据缺陷已经实测

`architecture.md §3.4` 的三源对照实验里，**4 只完全无关的股票
在 2011-12-02/05/13/14/15、2014-04-23 这几个日期上同步出现
10%–80% 的成交量分歧**。东方财富作为第三方仲裁判定：

- pytdx 对、东财对、腾讯**错**
- 2011-12-13 的腾讯数据为：close 11.80 / 量 2.05M
- pytdx + 东财的成交额反推均价为 11.47，落在 [11.00, 12.11] 自洽区间
- 腾讯声称当日最低 11.79，若按其成交量根本不可能出现 11 元的价格

影响面：恒生电子 / 贵州茅台 / 工商银行 / 平安银行各 4–6 根，
合计 **20 根 / 18018 = 0.11%**。看似小，
但**全在特定日期集中**、**不会报错**、**不会为空**、
只会安静污染指标和回测——这是最难发现的一类错误。

### 3.5 单次最多 640 根

`count` 参数上限 640。比 pytdx 的 800 略少，
拉 4000 根日线要翻 7 页（pytdx 5 页）。

### 3.6 没有财务/除权除息/板块/逐笔接口

腾讯 HTTP 的覆盖面集中在**行情层**：

| 能力 | 腾讯 | pytdx |
|------|------|-------|
| 日/周/月 K 线 + 复权 | ✅ | ✅ 但无复权 |
| 实时快照 + 名称 | ✅ | ✅ 但无名称 |
| 财务快照 | ❌ | ✅ |
| 除权除息 | ❌ | ✅ |
| 板块/行业/省份翻译 | ❌ | ❌（双方都没有） |
| 逐笔成交 | ❌ | ❌ |

需要财务/除权除息仍然要靠 pytdx 或本地通达信文件。

### 3.7 收录范围

接口只覆盖**已上市股票**，不提供**「全市场代码列表」**。
枚举「现在有哪些股票在交易」做不到 —— 需要靠代码表或本地 .tnf 文件。

## 4. 实测中的关键发现

### 4.1 量纲与单位

| 字段 | 腾讯 | pytdx 日线 | pytdx 周/月/季/年 |
|------|------|-----------|------------------|
| volume | 手（×100） | 股 | 手（×100） |
| amount | **无字段** | 元（精确） | 元（精确） |
| OHLC | 元（精确） | 元（精确） | 元（精确） |

**腾讯 vs 本地 `.day`**（本会话实测）：

| 项 | 表现 |
|----|------|
| OHLC 逐根 | **40/40 一致**（近 40 个交易日） |
| 开盘 / 最高 | 0 处差异 |
| 收盘 / 最低 | 0 处实质差异（2020+ 范围内） |
| 派生周期（周/月/季/年） | **行数与 pytdx 完全一致**（848/201/67/17） |

### 4.2 已知有缺陷的日期

腾讯 K 线在以下日期对所有受影响股票都是错的，**不要相信**：

```
2011-12-02  2011-12-05  2011-12-13  2011-12-14  2011-12-15
2014-04-23  2016-01-04（部分股票）  2010-03-12（平安银行）
```

详细机理见 [architecture.md §3.4](../docs/architecture.md) 「关键发现一」。
简单说：**腾讯和 pytdx 在这些日期上**互不兼容，且腾讯错的概率更高
（pytdx 自洽 + 东财独立确认）。

### 4.3 性能

| 操作 | 耗时 |
|------|------|
| 拉 4000 根日线（翻 7 页 × 640 根） | **2.6 秒** |
| 实时快照单次 | ~150ms |
| 名查询（复用快照接口） | ~150ms |

## 5. 复现命令

```powershell
cd D:\repo\03_pers-proj\zx-stock\server

# 单只实时快照 + 名称
.\.venv\Scripts\python.exe -W ignore -c "
import sys; sys.path.insert(0,'src')
from server.external import tx_kline
import json
print(json.dumps(tx_kline.fetch_quote('sh600570'), ensure_ascii=False, indent=2))"

# 拉 4000 根日线
.\.venv\Scripts\python.exe -W ignore -c "
import sys; sys.path.insert(0,'src')
from server.external import tx_kline
rows = tx_kline.fetch_history('sh600570', 4000)
print(f'{len(rows)} 根  {rows[0][\"trade_date\"]} ~ {rows[-1][\"trade_date\"]}')"

# 前复权 / 后复权
.\.venv\Scripts\python.exe -W ignore -c "
import sys; sys.path.insert(0,'src')
from server.external import tx_kline
for fq in ['', 'qfq', 'hfq']:
    rs = tx_kline.fetch_period('sh600570', 'day', fq, count=1)
    print(fq or '不复权', '->', rs[-1]['close'])"

# 整库同步到 tq-stock（用现有工具，对照实验标准流程）
.\.venv\Scripts\python.exe -W ignore tools\init_db.py --db tq-stock
.\.venv\Scripts\python.exe -W ignore tools\sync_tx.py sh600570 --db tq-stock

# 与 pytdx 库逐根对照（前提：两库都已同步）
.\.venv\Scripts\python.exe -W ignore others\compare_sources.py sh600570 --limit 8
```

## 6. 一句话复盘

腾讯是 **HTTP 路径里最干净的一个**，优势在复权和零客户端安装，
劣势在 K 线没有成交额 + 已被实测出 0.11% 的系统性数据缺陷。
**和 pytdx 不冲突**——两者能力圈几乎互补：
腾讯给复权，pytdx 给历史深度和成交额。
